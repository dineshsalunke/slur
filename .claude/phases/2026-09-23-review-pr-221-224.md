## #224 findings (worst first)

1. **MEDIUM — rail glow is wrong in the rear-view mirror.** Supervisor verified in source.
   `rail-glow.ts:28` — `u.uRailOrigin.value[ i ].copy( _world ).applyMatrix4( camera.matrixWorldInverse );`
   and `:30` for the direction put the uniforms in the MAIN camera's view space. `rear-view-pass.tsx:42`
   — `state.gl.render( state.scene, camera );` — draws the same scene with the rear camera, so the deck
   shader reads main-camera uniforms in rear-camera space. Hidden at x = 0; when the ship strafes by s
   the mirror glow shifts about 2s sideways (inferred). The same bug is in #221's rock key light at
   `rock-field.tsx:49` (`transformDirection( state.camera.matrixWorldInverse )`).
   Fix: pass world-space uniforms and transform in the shader with `viewMatrix`, or set them in
   `onBeforeRender` from the render camera.
2. **MEDIUM — the line light ignores rail gaps.** The old RectAreaLights turned off outside rail runs
   (`if ( ! run ) { light.intensity = 0; return; }`). `rail-glow.ts:6` draws two infinite lines at a
   constant `RAIL_X = HALF_WIDTH + RAIL_W / 2`. On gap segments with partial lane decks (`gaps.ts:119`)
   and at pit edges the deck glows from rails that are not there. The owner already finds pits hard to
   read. The y is also fixed at `lift`; floors are y = 0 today (`space.ts` `fullFloor`), so that part is
   latent. Fix option: a run-mask uniform, or a texture along z.
3. **MEDIUM — look, needs the owner's eye.** Only the deck receives rail light now. Rails, blocks,
   monoliths and the ship lose all local marigold spill. The substitute is the environment band, cut from
   0.5 to 0.1 (`tuning-schema.ts:26`, `'Env.bandIntensity': { value: 0.1`). The grey 0.6 sky sphere is
   replaced by the dark nebula. Blocks and ships will read much darker than on dev. Needs a live still.
4. **LOW-MEDIUM — measurement.** The 17.7 → 10.0 ms headline mixes removing the area lights with
   `antialias: false` (`canvas-gl.ts:5`). No row isolates MSAA. The PR's own phase note (:76) says
   *"`readPixels` on the default framebuffer does not wait under ANGLE Metal. Not resolved."*
   `antialias: false` itself is correct: `scene-effects.tsx` uses `<EffectComposer multisampling={ 0 }>`
   and the rear view has its own FBO with `samples: 4`.
5. **LOW — semantics.** The panel still labels `skyIntensity` (`tuning-panel.tsx:45`), but it is now the
   nebula gain in the light cube. `Environment.rotation` still rotates `scene.environment`
   (`scene-environment.tsx:10`), so any non-zero value makes reflections disagree with the visible sky.
6. **LOW — shader.** `fwidth( r )` (`nebula-shaders.ts:171`) follows a non-uniform early return (`:167`,
   `if ( cosA <= 0.0 ) return`). Derivatives are undefined in divergent control flow. At most AA noise on
   the planet edge.
7. **LOW — docs.** `ADD.md:191` says *"one large planet for Deep Space, two small moons for Nebula"*.
   `nebula-presets.ts` has `planetSize: 21` (:58) and `moons: 0` (:66) for Nebula, and `moons: 0` for
   Deep Space (:85).
8. **MERGE** — the `net-canvas.tsx` conflict is imports plus the `gl={ CANVAS_GL }` line. Trivial.

## #221 findings

1. **MEDIUM — first-frame and tunable bake hitch not measured.** The bake shades a 1024² × 6-face cube:
   2 warp levels of 3×fBm(4), 4 billow(6/4), 2 Worley (27 cells each) (`nebula-baker.ts:17`, `:183`),
   then a synchronous `readRenderTargetPixels` (`:263`). It runs on the first frame and on every bake-key
   change. Only the live pass is measured (0.62 / 1.05 ms). On a weak iGPU it could stall long or risk a
   context loss (inferred). Ask for one number.
2. **MEDIUM — docs are wrong.** `ADD.md:258` — *"If a map is missing, the rocks degrade and the game does
   not crash."* `rock-field.tsx:18` calls `useTexture( ROCK_TEXTURES )` with no Suspense or error boundary
   around `GameEnvironment`. A 404 throws through R3F's Canvas to the route (inferred, not tested). Fix
   the claim or add a boundary.
3. **LOW — assets.** Three 1024² JPGs: diff 533 KB, arm 696 KB, normal 1007 KB = 2.2 MB, plain git
   (`.gitattributes` puts only `public/models/**` in LFS). Poly Haven `dark_rock` is CC0 (recalled). The
   normal map as JPG carries block artifacts (cosmetic). Texture load grows from 368 KB to 2.2 MB.
4. **LOW — scope.** `.gitignore:44-45` adds `.tmp/` with a comment about *"Session handovers
   (yeet:pause)"*, from the author's tooling. Unrelated to #215. Drop it.
5. **LOW** — the drei `<Stars>` ref callback in `deep-space-sky.tsx` mutates drei's material
   (`transparent=false`, `depthTest=false`). Works, but depends on drei internals.
6. **INFO** — GPU memory: field cube 1024² × 6 RGBA8 ≈ 24 MB, noise volume 1 MB, 128² half-float cube.
   Not stated in the PR. Acceptable.
7. The drei env removal lands in #224, not #221. #221 keeps `SceneEnvironment` for the track.

## Non-negotiable acceptance gates (this project — pass/fail, not style)
1. **Re-render isolation (the #1 rule).** The `<Canvas>` parent (`GameShell`) holds **ZERO reactive state** →
   `<NetCanvas>` never re-renders. ALL live run-state subscriptions live in the `<Overlays>` **leaf** sibling.
   A re-render in an overlay must never re-render the WebGL scene. (`conventions/r3f.md`,
   memory `think-rerender-subscription-impact`.)
2. **Colyseus state is NOT React-reactive.** Never read `room.state.*` during render. Bridge it via
   `getStateCallbacks(room)` + `.listen(...)` / `players.onAdd/onChange/onRemove` → `setState`
   (memory `colyseus-state-not-reactive`).
3. **Loop↔UI seams are MODULE SINGLETONS, not props/state** — spectator target + local role are read by the
   R3F `useFrame` loop every frame; they must live outside React (same idiom as `input/keyboard.ts`). Never
   prop-drill them into `NetLoop`.
4. **Every `useEffect` carries the mandatory justification comment** (external system + which cheaper idiom it
   rejects). Prefer render-derivation / event handlers / refs / module singletons first (`conventions/r3f.md`).
5. **House React style:** `<Fragment>` not `<>`; **one component per file** (hooks/helpers/constants may share).
6. **Never couple the room/socket to a component lifecycle** — `room.leave()` only on a deliberate Leave
   action, never in an unmount cleanup (the S2 bug). The room lives on `session` (already true).
7. Verify: `pnpm typecheck` + `pnpm --filter @slur/shared test` (unchanged, 28 GREEN) + `pnpm lint`
   (only the pre-existing `net-canvas.tsx:106` complexity debt may remain) all green.

## Component tree (re-render safety is structural)
```
routes/game/route.tsx

    <GameShell seed>                      ← NO reactive state → NetCanvas stable
      <NetCanvas seed/>                   ← the WebGL scene (existing); mounts once, never re-renders

```

```ts
// Spectator state OUTSIDE React — read by the R3F loop each frame, set by DOM (Tab / ◀▶). Same idiom as keyboard.ts.
export const localRole = { spectating: false };                 // mirrored from PlayerState.spectating by the ECS bridge
export const spectatorCam = { targetSessionId: null as string | null };
export function cycleSpectatorTarget(racerIds: string[], dir: 1 | -1 = 1): void {
  if (racerIds.length === 0) { spectatorCam.targetSessionId = null; return; }
  const i = racerIds.indexOf(spectatorCam.targetSessionId ?? '');
  spectatorCam.targetSessionId = racerIds[(((i < 0 ? -dir : i) + dir) + racerIds.length) % racerIds.length];
}
```

## 3D lobby preview = REUSE the main scene (NO 2nd Canvas)  ← decision revised
Lobby/countdown/racing/results are PHASES over the ONE persistent gameplay Canvas — the local ship is
already on the start line during lobby. So the "preview" is a **lobby camera mode** that hero-orbits the
local player's real ship (picking a ship/colour already swaps its model live via the ECS bridge → WYSIWYG).
**No dedicated preview Canvas.** Implement:
- `camera/chase.ts` += `updateLobbyCamera(cam, world, dt)` — slow hero-orbit around `queryFirst(LocalPlayer,
  Render)`; module-level `let orbitAngle` advanced by dt; rubberband ease; fixed ~55 FOV; lookAt the ship.
- `spectator.ts` += `export const runPhase = { value: PHASE.lobby };` (the loop reads phase without React).
- `net-canvas.tsx` bridge: `getStateCallbacks(room)(room.state).listen('phase', v => { runPhase.value = v; })`.
- `net-loop.tsx`: camera branch = lobby → `updateLobbyCamera`; else spectating → spectator; else chase.
  Predict ONLY when `runPhase.value === PHASE.racing && !localRole.spectating` (frozen otherwise — matches server).
- `lobby-overlay.tsx`: lay controls around the EDGES (roster left, pickers bottom, GO bottom-right) so the
  centered orbiting ship shows through. No `<ShipPreview/>` component — it's the real scene.

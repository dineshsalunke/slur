## Ideate  (2026-08-10)

### The framing: four gaps between "works" and "feels like SLUR"

| # | Gap today | Part | Character | Size |
|---|-----------|------|-----------|------|
| 1 | Ships **move** different (S3 flight tuning) but **fight** identical — same stun, same bolt | armour/`powerAffinity` combat stats | gameplay data + hit math | small |
| 2 | Choice is **invisible** — dev hot-swap keys 1–5, no commitment moment | real lobby ship-pick UI | UI (preview exists from S4) | small–med |
| 3 | It's **silent** — zero audio in the codebase | audio pass | **new subsystem** | large |
| 4 | It's **programmer-neon** — ADD aesthetic unredeemed | art/juice pass | polish (bounded by checklist) | bounded |

### Decisions locked this phase

- **Scope = full S6** (all four parts) — user chose, over my split-it recommendation. Accepted
  **on condition part 4 has a finite checklist** so "S6 done" stays answerable.
- **Center of gravity = all equal weight.** Sequence by *dependency only*, not felt-impact.
  Dependency map: **1 → 2** (pick screen renders part-1 stats); **3 and 4 fully parallel**.
- **Armour = sidegrade ONLY.** `armour` is the *readable name* for a tradeoff the flight tuning
  already imposes (big ship = tanky **and** sluggish), NOT a free stat. No "tank strictly better"
  axis. Upholds [[balance-at-playstyle-not-geometry]]: fairness = every ship has a viable
  win-con, not stat-equality.

### Design bets to validate in Brainstorm (not yet locked)

- **Audio should be SYNTHESIZED, not sampled** (SFX at least). A filtered Web Audio oscillator
  whose pitch tracks speed is *more* SLUR than a looped mp3 — fits TRON, dodges asset-licensing,
  matches the "deterministic, no baked geometry" ethos. Music may still be a track. → research
  Web Audio vs Tone.js vs sampled; positional model.
- **Audio architecture is a NON-NEGOTIABLE, not a detail.** Audio graph = long-lived resource →
  module singleton **outside React** (same rule that cost S2: no lifetime coupled to a
  `useEffect` cleanup). Positional panning driven off ECS in `useFrame`, never React state.
- **Part-4 checklist (starting bid, to finalize in Prep):** TRON **derezz-death** + ship **trail**
  + **LCARS HUD frame**. Everything else (comfort sliders, extra shaders) is explicitly OUT of S6.

### Success = human gate

Two-tab playtest where: you **pick** a ship on a real screen (not dev keys), the pick **changes
how it fights** (armour/affinity readable in play), you can **hear** engine/hit/pickup, and death
**derezzes**. If all four land and the balance philosophy still holds → S6 done.

## Brainstorm  (2026-08-10)

Grounded every question in the actual code first (combat/constants, ship-classes, schema,
lobby-overlay, explosions). Two "open questions" partly dissolved on contact with the code.

### Decisions locked

- **Q1 · armour = per-class stun-duration multiplier.** New `stunResist` (or `armour`) field in
  `ship-classes.ts` FlightTuning (or a sibling combat block); server + client both resolve it →
  `effectiveStun = STUN_SECONDS * (1 - armour)` applied where `stunTimer` is set. **Stun is a
  predicted SimShip field**, so armour MUST live in the shared registry (byte-identical both ends)
  or prediction desyncs — same discipline as flight tuning. Sidegrade axis: **agile = fragile
  (long stun), heavy = tanky (short stun)**; agility ⊥ armour, no free stat. Upholds
  [[balance-at-playstyle-not-geometry]].
- **Q2 · `powerAffinity` DEFERRED.** Roster is one item (Bolt); affinity is meaningless until
  Mine/Shield/Boost exist. Add it with the 2nd pickup, not now. Part-1 = armour only.
- **Q3 · Audio = the AUDIO-doc approach.** three.js `PositionalAudio` (Web Audio), object-pooled,
  client-local, **CC-sourced samples**. Split: **engine hum = synthesized oscillator** (continuous
  pitch∝speed — the one cue a sample loop can't do cleanly); **all discrete SFX = CC sample files**;
  music = a CC synthwave track. No Howler for v1 (revisit only if bus/ducking needs it).
  - **ARCHITECTURE (non-negotiable):** AudioContext + master/duck buses = **module singleton
    OUTSIDE React**, resumed on first user gesture (host Start / player Join click). Per-ship
    `<PositionalAudio>` MAY be R3F (lifetime == ship entity). Never couple the context to a
    `useEffect` cleanup (the S2 bug). Bind SFX to the S5 events already broadcast (`usePowerUp`
    fire, `'hit'`, `stunTimer` edge, pickup grab, threat-HUD → incoming blip).
  - **Mix/duck order** (from doc §5): threat > own combat/impact > pickups/UI > engine > music.
    Master limiter + a fast mute/volume control (office).
- **Q4 · Pick UI mostly already exists.** `lobby-overlay.tsx` already picks ship+colour
  (`SET_CLASS_MESSAGE`), locks at GO, and shows the hero-orbit. Part-2 = **upgrade the picker to
  show IDENTITY**: class name + armour/agility profile + a real card (not a lowercase chip). Dev
  keys 1–5 stay as in-game hot-swap. Much smaller than backlogged.
- **Q5 · derezz = dissolve shader + keep the burst.** Noise-threshold clip on the ship model
  (authentic TRON dissolve) as the death; existing `explosions.tsx` shard-burst stays as the
  shatter accent. Trail = drei `<Trail>` for v1 (revisit perf at 8–12 ships against r3f.md).

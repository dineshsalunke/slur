## 1. The model (owner, via slur-supervisor)

- The track is a **score**. The notes are inputs: `L`, `R`, `J` (jump), a held strafe (`R→`, `L→`), `SMASH`
  (a fractured block) and rest (`·`). Example: *"L, L, R→, J, J, R→, ·, ·, ·, ·, R, R…, J, L, L"*.
- **Tempo is a distance grid.** Notes sit at fixed track z. A faster ship plays the same song faster.
- **Patterns** come from a motif library (3–8 notes) with variation: repeat, mirror L↔R, stretch, chain.
  Intensity picks the denser motifs.
- **The generator is inverted.** The score comes first. Then the geometry that forces each note. A note is
  placed only where the contract ship can play it (strafe acceleration included), so #246 is fixed by
  construction.
- `SMASH` carries its own rest: the fracture-shadow zone. #248's `sealShadowed` becomes a test.
- **Register gap (rev 2).** After every note the player gets **0.5 s of calm** before the next note starts.
  It is measured at max speed (`FASTEST_CRUISE`, 124 today) and counted from the **end** of the previous
  move: the strafe has settled, or the jump has landed. It applies to every pair: L→R, L→L, strafe→jump,
  jump→strafe, J→J. The owner: *"we cannot literally have a left and then an instant right"*.

## 2. What this changes in the accepted design

1. `docs/DECISIONS.md` ADR-006 §1: *"The music is **hidden pacing scaffolding only** — the surface stays
   **continuous/organic, never a rhythm game** (no discrete notes, no lane-snapping)"*. R4 makes the notes
   the design unit. The **sim stays continuous** (GDD §0 is untouched): the note grid and the lateral step
   are authoring grids, like `CELL`. But the player *can* learn the notes, and that is the point. The owner
   should overrule this line on purpose.
2. ADR-006 fairness: *"no two in a row"* (gaps), pinned by `sim/track.test.ts:236` *"no two gaps in a row
   and none in start-safe"*. **Rev 2: no conflict.** Under the register gap two jump notes sit ≥ 140u apart,
   i.e. ≥ 7 segments (§4.4).
3. ADR-013: *"The procedural generator reads a single **`TRACK_CONTRACT`** … and **never reads
   `SHIP_CLASSES`"*. The register rule is stated at `FASTEST_CRUISE`, and `FASTEST_CRUISE` is a max over the
   roster (`ship-classes.ts`: `Math.max( ...ALL_CLASS_TUNINGS.map( ( t ) => t.maxCruise ) )`). Read directly,
   a Freighter speed edit would move every note on every seed. §4.2 proposes a frozen contract field.
   `FRACTURE_SHADOW_Z` (#248) has the same defect today: it is a max over `SHIP_CLASSES`.

Kept: ADR-006's macro **envelope** (`SECTIONS`, `intensityAt`), ADR-007 (block height 8u, free width and
depth), GDD §0 clearance.

## 4. Note spacing (rev 2 — replaces the 32u pitch)

### 4.1 The rule, as named constants

```ts
REGISTER_GAP_S   = 0.5
REGISTER_CRUISE  = TRACK_CONTRACT.registerCruise           // 124, frozen (see 4.2)
REGISTER_GAP_Z   = REGISTER_GAP_S * REGISTER_CRUISE         // 62u
noteMove( n )    = settle / air time of note n for the contract ship, measured by a simulate() pilot at module load
noteSpacing( n ) = REGISTER_CRUISE * ( noteMove( n ) + REGISTER_GAP_S )   // onset of n → earliest onset of the next note
```

This is the same shape as `FRACTURE_SHADOW_Z = FRACTURE_SHADOW_S * max( smashKeep * maxCruise )`. The spacing
depends only on the **previous** note. The next note's kind does not matter: the calm is counted up to the
next note's **start**.

### 4.2 Which speed

Options for `REGISTER_CRUISE`:

| # | Source | Seeds move when a ship is retuned? | ADR-013 |
|---|---|---|---|
| V1 | `FASTEST_CRUISE` live (a roster max) | **yes, every seed** | breaks it |
| V2 | **`TRACK_CONTRACT.registerCruise: 124`**, frozen, plus a guard in `rosterContractFailures`: no class `maxCruise` above it | no | keeps it |
| V3 | `pacingCruise` 55 | no | keeps it, but the calm at 124 u/s would be only 0.22 s: breaks the owner's rule |

**Recommend V2.** It holds today's 124 exactly, so the owner's rule is met to the number. A class faster than
124 then fails at module load, the way a too-wide class fails today. Raising the cap is a deliberate reshape,
fenced by the frozen-geometry test. The same field should replace the roster max in `FRACTURE_SHADOW_Z`.

| `L`/`R` 2 cells (8u) | 0.550 s | 1.050 s | 130.2u | **140u** (7 segs) |

130.2u (2 cells).

|---|---|---|---|---|---|

the least (0.6–0.76 s), the Interceptor the most (1.15–1.47 s). Q3 asks the owner if that is acceptable.

### 4.4 Does the 32u grid survive?

No. 32u came from rev 1's dense ceiling, and the register rule replaces that ceiling. What stays is a
question of how onsets are quantized.

| # | Grid | How a note's spacing is expressed | Waste vs raw | Segment fit | Learnable rhythm |
|---|---|---|---|---|---|
| G1 | 32u grid + min-spacing rule on top | round up to a 32u multiple (128 / 160 / 128 / 224) | up to 30u | straddles 20u segments | weak: the rests between notes vary |
| G2 | one beat = the worst single-note spacing (140u); `JJ` = 2 beats | every note is 1 beat | up to 33u (L1) | aligned | strong, but every note sounds the same length |
| G3 | **note durations**: each note lasts `noteSpacing( n )` rounded up to `SEG_LEN` 20u; a rest `·` is a fixed unit | L1 = 6 segs, L2 = 7, J = 7, JJ = 11 | ≤ 20u | **aligned** | strong: short and long notes, like quarter and half notes |
| G4 | continuous (4u `CELL`) + min-spacing rule | exact | ≤ 4u | straddles | none |

**Recommend G3.** The beat does become the register spacing, but per note, not one number for all. A note
starts on a segment boundary, so rev 1's straddle problem (ADR-019: *"A block never leaves its segment"*)
disappears, and a `J` gap is one segment, as gaps are today. Rev 1's Q2 is superseded.

The rest unit is open (Q4). Suggestion: 3 segments (60u), about the register gap. So `· · · ·` = 240u =
1.9 s at 124 u/s and 4.4 s at 55 u/s.

### 4.5 "J, J" and ADR-006

- Two jumps now start ≥ 140u apart (7 segments). They cannot sit in adjacent segments, so ADR-006's *"no two
  in a row"* holds on every score track. The test at `track.test.ts:236` runs on both generators unchanged.
- *"J, J"* = two separate jumps, 140u apart. A double jump is its own note, `JJ`, lasting 220u. Both are
  legal and neither conflicts with anything. Rev 1's Q3 resolves itself.

### 4.6 Density — how many notes a track holds

| | Notes on a 7,880u track |
|---|---|
| Every note an L2 (140u), no rests | 56 |
| Every note an L1 (120u), no rests | 65 |
| Envelope-scaled (mean intensity 0.499 × 56) [inferred: linear in intensity] | **~28** |
| Today, for comparison: blocks per track (ADR-019, 4,194 blocks over 9 seeds) | ~466 |

At peak (final chorus) a note comes every 140u: 1.13 s at 124 u/s, 2.55 s at 55 u/s. Rev 1's peak was one
per 32u, so peak density falls **4.4×**. A score track has about **16× fewer** forcing objects than today's
block count.

## 5. Notes → geometry

### 5.1 The note table

`s` = the lateral step: 1 cell (4u) or 2 cells (8u, `MIN_LANE`). The score line `x(z)` is the sum of the
steps. It is an authoring line: the sim never reads it.

| Note | ASCII | What the player does | What the geometry places | Duration (G3) |
|---|---|---|---|---|
| Left / right, 1 cell | `l` `r` | a 4u sidestep | a 4u-deep blocker on the old line at the onset | 120u |
| Left / right, 2 cells | `L` `R` | an 8u sidestep | as above, wider | 140u |
| Held strafe | `<` `>` | hold the key; drift ≤ `WEAVE_SLOPE_CAP` 0.839 u/u | a diagonal channel | length + 62u |
| Jump | `J` | one jump | a gap ≤ `jumpReach` (23.8u at 55) at the onset | 140u |
| Double jump | `JJ` (one token) | jump, then jump in the air | one gap ≤ 0.8 × 63.2u | 220u |
| Smash | `S` | fly through, or shoot | a fractured block on the line, sealed either side | ≥ 80u |
| Accent | `!` + note | the same note, no way round | the blocker becomes a full pinch gate (`PINCH_*`) | as its note |
| Rest | `.` | nothing | open line; filler only (§5.3) | 60u (Q4) |

A partial gap (a floor strip beside the hole) is a **mode fork** (R1 §3.1): `J` or a strafe. It is written
`J|R` and handled as a two-voice fork (§7).

### 5.2 How hard does a note force?

A note is "forced" when the easiest route must play it. Test: the Viterbi **easiest** route plays ≥ X% of the
score's notes (the *adherence*). The hardest route keeps the Viterbi cost (owner ruling).

| # | Forcing | Adherence | Look | Block count | Reuses |
|---|---|---|---|---|---|
| M1 | **Gate per note**: the slice is closed except a hole at the new line | 100% | a wall every 120–220u | high | pinch gate |
| M2 | **Cone gate**: close only what the fastest strafer reaches between notes at pace | ~100% at pace | walls near the line | medium | pinch gate |
| M3 | **Blocker only** on the old line | unknown; measure | sparse | lowest | flick pillar |
| M4 | **Score-steered band**: today's open band (`corridor.ts`) centred on the score line, not the weave; notes are blockers inside it | set by band width; measure | like today | as today | band, flick, pinch, noise walls |
| M5 | **Carved field**: wall density 1 outside a hull-wide channel | 100% | a solid maze | very high | noise walls |

Rev 2 note: notes are now ≥ 120u apart, so a wall per note (M1) no longer reads as the *"claustrophobic
tube"* ADR-006 rejected. It reads as a gate every 1–2.5 s. M1 is now a fair candidate. M5 is still a tube.

**Recommendation: M4, with M1 for accent notes** (unchanged). Adherence is the measured dial. Q5.

### 5.3 Filler — geometry that carries no note (rev 2)

About 28 notes cannot fill a track that holds ~466 blocks today. The space between notes needs geometry that
asks for no input. Rule for all filler: it stays out of the **calm tube**, the line ± (hull 2u + a margin)
from the end of a move to the next onset. So a ship on the line never has to steer during the calm.

| # | Filler | Asks for input? | Look | Notes |
|---|---|---|---|---|
| N1 | Decor outside the deck only (pillars ADR-018, asteroid bands) | never | empty deck | the deck reads bare |
| N2 | **Band walls**: M4's band edges as walls beside the calm tube | only if you leave the line | framed lane, like today | reuses `corridor.ts` + noise walls |
| N3 | **Harmony blocks**: blocks off the line, clear of the calm tube, that frame and preview the next note | only if you leave the line | busy, like today | a readability gain |
| N4 | **Optional notes**: pickups or fractured blocks off the line, as a reward | only if you choose | busy | pickups are the reward axis; an optional note inside the calm is a choice, not a demand |

**Recommend N2 + N3, with N4 for pickups.** The band walls are M4's forcing geometry anyway. Q6 asks the owner
to confirm that off-line blocks are allowed during the calm, and how wide the calm tube is.

## 7. Forks and arms (R1)

A fork is **two voices**. The score splits into arm A and arm B, then they rejoin.

- Each arm is its own note list, with the register gap inside each arm. Example: arm A `R J L` (a pickup on
  it) · arm B `. . > .` (quiet).
- R1's rules apply as they are: each arm ≥ 25u, arms ≥ one hull apart, no dominated arm. A mode fork (`J|R`)
  is a fork whose arms differ only in mode. The choice itself is a note: the register gap applies before the
  split.
- **Pickups are the reward axis** (owner ruling). A fork puts its pickup on the harder arm. A single-voice
  phrase may place an **ornament** (N4). Pickup anchors on `'score'` tracks use a new id scheme. The ADR-002
  test *"pickup anchor id/position scheme is unchanged"* stays pinned to `'weave'` tracks.
- **Traps**: owner ruling *"regenerate a segment that has a trap"*. On a `'score'` track a trap can only come
  from off-score geometry (dividers, band walls, filler). The rule: re-roll the phrase variation with
  sub-seed `hash(seed, phraseIndex, attempt)`, at most N attempts, then fall back to a rest phrase. It stays a
  pure function of the seed.

## 8. The per-class check

1. **Module load (like `rosterContractFailures`).** The `simulate()` pilot measures `noteMove( n )` for the
   contract ship (§4.1). Each motif is then built alone and flown by the contract ship at 55 u/s and at
   `REGISTER_CRUISE`. A motif that fails **throws**. The same pass records each class's calm per note (the
   §4.3 table) as data, a candidate for the ship-select screen.
2. **Per track (test).** A seed test flies the whole score line for every class, and asserts ≥
   `REGISTER_GAP_S` of calm after every note at the class's own `maxCruise`.

The pilot models acceleration. Memory `rate-clamp-is-not-flyability.md`: *"pacing paths obey the per-row
rate clamp but ignore strafeAccel; fly the path with a sim pilot to prove it (#246)"*. So #246's `PathSolver`
is not the check. It stays a board tool.

## 9. The motif file format

Ship stats are data (non-negotiable #6), so motifs are data.

| # | Format | Owner can edit | Type-checked | Validated |
|---|---|---|---|---|
| F1 | TypeScript objects in `@slur/shared` | yes, but verbose | yes | module load |
| F2 | JSON file + a validator | yes | no | module load |
| F3 | Note strings, e.g. `'L L > J J > . . . . R R J L L'` | **yes — the owner's own notation** | no | parser at module load |
| F4 | F1 objects that hold F3 strings | yes | fields yes, notes by parser | module load |

**Recommendation: F4.**

```ts
{ id: 'stairs', notes: 'L L L .', intensity: [ 0.3, 0.8 ], weight: 2, mirror: true, stretch: [ 1, 2 ] }
```

- The string lists notes only. Spacing is never written: each note's duration comes from §4.4 G3, so a motif
  cannot break the register gap.
- Variation is a pure function of `(motif, sub-seed)`: repeat ×n, mirror (swap `L↔R`, `<↔>`), stretch
  (insert rests), chain. Reversal is not offered: it would move a `S` rest before the smash.
- The line stays inside the deck: when a motif would run past the band edge, the mirror is forced.
- A frozen digest of the library joins `track-contract.test.ts`. Editing a motif reshapes every `'score'`
  seed.

## 14. Caveats

- Move times are **measured** with `simulate()` at 60 Hz, so they are quantized to 1 tick (16.7 ms). The
  settle tolerance (±0.25u, ±1 u/s) is my choice. A looser one shortens the moves.
- The strafe pilot uses the best counter-press timing. A real player is slower. So the spacing is a
  **floor**, and the real calm is shorter than the table shows. Playtest (S5) sets the margin.
- Notes per track (~28) assumes density is linear in intensity [inferred]. The composer (S2) measures it.
- Adherence for M3/M4 is **not measured**. The transcriber (S0) measures it on today's tracks first.

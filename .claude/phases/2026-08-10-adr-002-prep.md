# 2026-08-10 — ADR-002 PREP: Track anchors (visual seam FROZEN)

**Phase:** Prep (design settled; concrete diff deferred until ADR-001 is built). **ADR:** `docs/DECISIONS.md` ADR-002.
**Depends on:** ADR-001 landed (the `resolveTrack` provider). Implement order: ADR-001 → ADR-002.

## Scope decision (settled with user, after testing "build both")
- **BUILD (a): first-class `Track.anchors`.** The gameplay-placement layer of the 3-layer model.
- **FREEZE (b): the physics/visual split abstraction.** The `resolveVisual(descriptor) → VisualTrack` seam is
  **parked** — kept only as the documented **WYSIWYG-collision rule** (`docs/ADD.md` hard rule #6), no code.
  The client keeps rendering physics `Segment`s directly (`track-view.tsx` unchanged). Unfreeze when an
  authored provider or the art pass needs the visual to diverge from the hull. *(User tightened scope: the
  seam is speculative until it has a real second consumer.)*

## The anchors design (half a)
```ts
interface Anchor { id: string; kind: string; x: number; y: number; z: number; params?: unknown }
// Track gains: anchors: Anchor[]  — materialized by the provider (NOT synced; positions derive from descriptor)
```
- **`kind: 'pickup'` modelled concretely; `kind` left open (string)** for future hazard/drop/checkpoint.
  Do NOT build kinds with no consumer yet (same anti-pattern as the frozen visual seam / ADR-003 grammar).
- **procgen emits anchors while materializing the track.** `pickupLayout()`'s logic moves INTO the procgen
  provider; **`corridorCenterX` becomes provider-internal** → the LAST seed reach-around ADR-001 left at the
  pickup seam dies here.
- **Pickups become a read:** `track.anchors.filter(a => a.kind === 'pickup')` (replaces `pickupLayout(descriptor)`).
- **Wire impact ≈ nil:** anchor positions are materialized (derived both ends, not synced); layer-2
  availability is the EXISTING `RunState.pickupTaken` MapSchema, keyed by anchor id (was pickup-slot id — same
  shape, now generalised).

## Invariant check (ADR-000)
- Inv-1 (descriptor synced, Track local): anchors are part of the materialized Track ✓.
- Inv-2 (Track = gameplay data, no visuals): anchors are gameplay placements ✓; visuals stay out (frozen seam).
- Inv-2 litmus for future kinds: "would two clients disagreeing on this anchor desync the game?" yes → it's a
  real anchor; a purely cosmetic marker would NOT be an anchor (it'd be VisualTrack data, frozen).
